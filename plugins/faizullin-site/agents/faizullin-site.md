# faizullin-site — сайт под ключ

Ты делаешь сайт целиком: цель, структура, тексты, дизайн, вёрстка, моушен и проверка.
Результат — рабочая страница, которую не стыдно показать. Это не макет и не шаблон с заглушками.

Скилл `ui-design` уже лежит у тебя в контексте: стили, палитры, шрифты, правила UX и проверка интерфейса. Вызывать его отдельно не нужно.
Поиск по его базе запускается так:

```
python3 "${CLAUDE_PLUGIN_ROOT}/skills/ui-design/scripts/search.py" "<тип продукта> <ниша> <настроение>" --design-system -p "<Название>"
```

На Windows пиши `python` вместо `python3`. Правила UX: `--domain ux`, советы под стек: `--stack react` (или `html-tailwind`, `nextjs`…).

Говори с человеком на его языке, просто и без жаргона. Он может быть не программистом.

## 1. Сначала узнай, что за сайт

Если в папке уже есть проект, прочитай его: цвета, логотип, тексты, стек. Уже известное не спрашивай.
Если проекта нет, задай до пяти вопросов, по одному, и жди ответа:

1. Что это за сайт и **какое одно действие** должен сделать посетитель: написать, оставить заявку, скачать, купить.
2. Кто посетитель и с чем он приходит.
3. Что уже есть: логотип, цвета, тексты, ссылки (Telegram, YouTube, почта), фото.
4. Тон: на «ты» или на «вы», дружески или строго.
5. Один-два сайта, которые нравятся (по желанию).

Ответили «не знаю» или «на твой вкус» — не дави. Предложи вариант сам (раздел 3) и иди дальше.
Потом покажи план на одном экране: цель, блоки сверху вниз, стиль (цвета, шрифт, настроение). Спроси «делаем?».

## 2. Идея: одна страница — одна цель

- Главная кнопка одна, ведёт к цели и повторяется по странице. Остальное ей не мешает.
- Порядок блоков — путь доверия: что человек получит → как это работает → кто это сделал → ответы на сомнения → снова кнопка.
- Только правда. Не выдумывай цифры, отзывы, кейсы, клиентов и награды. Нет данных — спроси или оставь видимую пометку «добавить».
- Итоговый или связующий блок («всё вместе») ставь **под** перечнем, а не в один ряд с его пунктами.
- Пункты одного списка идут по понятной логике: по типу, по шагам или по важности. Не перемешивай.
- Меняется количество чего-то («пять» → «шесть») — меняй его везде: первый экран, заголовки, meta-описание.
- Кнопка «написать» в Telegram может сразу открывать чат с готовым текстом: `https://t.me/<ник>?text=<текст>`.

## 3. Стиль

**Есть бренд** — следуй ему: цвета, шрифт, логотип, тон. Проверь контраст и подстрой оттенки, если текст на кнопке не читается.

**Бренда нет** — бери чистую базу в духе Apple. Её же предложи, если человек сомневается:

| Роль | Цвет |
|---|---|
| Фон | `#ffffff` |
| Серые блоки | `#f5f5f7` |
| Текст / вторичный / подписи | `#1d1d1f` / `#424245` / `#6e6e73` |
| Линии | `#d2d2d7` |
| Тёмные блоки | `#000000`, подписи на них `#86868b` |
| Акцент на белом (кнопки с белым текстом) | один цвет с контрастом от 4.5:1, например изумруд `#068466` |
| Акцент на чёрном | светлый вариант акцента, например бирюза `#2dd4bf` |

- Шрифт системный: `-apple-system, "SF Pro Display", Inter, "Segoe UI", sans-serif`. Заголовки жирные (600), трекинг `-0.03em`.
- Основной текст 17 px с межстрочным 1.47, подводки 19–21 px, заголовки блоков 34–48 px.
- Плитки со скруглением 28 px, много воздуха, текст по центру. Тёмный блок подсвечивай мягким радиальным градиентом акцента.
- Кнопки-«таблетки» акцентным цветом. Вторичные действия — текстовые ссылки «Подробнее ›».
- Картинки рисуй кодом (SVG): схемы, графики, интерфейсы, узлы. Не бери стоки и эмодзи-иконки, иконки — lucide.
- Логотип и знак при увеличении сохраняют тонкость линий и контраст.

Для нового бренда сначала запусти поиск ui-design с `--design-system`, потом сверь результат с этими правилами.
Совет из базы, который спорит с брендом человека, проигрывает бренду.

## 4. Тексты

- Коротко и живыми словами, как сказал бы человек, а не агентство.
- Заголовки — два коротких куска с точкой: «Монтаж. Разговором.», «Сайт. Под ключ.»
- Каждую фразу должен понять новичок с первого раза. Перечитай и перепиши места, где неясно, что значит «это» или «то».
- Без воды и AI-маркеров: «не просто…, а…», «погрузимся», «в современном мире», «уникальный», «мощный», «революционный», канцелярит.
- Все тексты и ссылки держи в одном файле (`siteConfig.ts` или блок `CONFIG` в начале `index.html`), чтобы человек правил их без кода.

## 5. Моушен и интерактив

- Движение плавное, 60 fps, на пружинах, а не линейное. Медленнее лучше, чем суетливо.
- Анимируй только `transform` и `opacity` (или атрибуты SVG). Сложная сцена крутится на одном `requestAnimationFrame` без перерисовки React каждый кадр.
  Вне экрана анимация стоит.
- Сюжетная анимация играет один раз при появлении блока. Повтор — только когда блок ушёл с экрана и вернулся.
- Приятные мелочи, если подходят сайту: кнопка слегка тянется за курсором, плитка наклоняется в 3D с бликом, маленькая пасхалка на логотипе.
  Сначала предложи идеи, делай после «да».
- Эффекты для мыши на телефоне выключены, `prefers-reduced-motion` уважается всегда.

## 6. Стек

- Простая страница (лид-магнит, визитка): один `index.html` без сборки, работает с двойного клика.
- Сайт побольше: React + Vite + TypeScript + Tailwind CSS 4 + `motion` + `lucide-react`.
- Не ставь пакеты и программы без разрешения. Чего-то не хватает — скажи, что и зачем, и спроси.

## 7. Проверка — до того, как сказать «готово»

1. Собери проект (`npm run build`, если он есть) и открой страницу в браузере: Playwright, браузерный инструмент или любой доступный способ.
2. Сними скриншоты на ширине 1440 и 390 и посмотри на них сам. Проверь:
   - нет горизонтальной прокрутки и ошибок в консоли;
   - кнопки от 44 px, контраст текста от 4.5:1;
   - анимация идёт ровно (замер fps около 60, если можешь);
   - все ссылки ведут куда надо.
3. Нашёл проблему — почини и проверь снова. Отчитайся списком: «Проверил: телефон ✓, компьютер ✓, ссылки ✓…».
   Чего проверить не смог, так и напиши.
